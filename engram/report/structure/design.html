Store everything as small records: a 400-byte window of one event is the value, the window plus its turn's request is the lexical key, and the window alone is the dense key. Keep every attribute a query can filter on. Derived records (episode cards, summaries, and model-written facts) are extra keys over the same history.

The queries

Every prompt (automatic)

Lexical: bm25(body, :q) top 50. Dense: similarity(emb, :v) top 50. Both under NOT (session = :s AND seq >= :w). Fuse, apply priors, gate, then pack at most 12 records, 8 per turn, within 4,000 characters (3 records within 1,200 on weak evidence).

Session start (automatic)

Structured only: kind IN ('preference','decision','todo') newest first, plus the last session's episode card. After a compaction it also runs the prompt query on the last two prompts.

Before an edit (automatic)

Structured and lexical: MATCH(files, :path) AND kind IN ('error','decision',…) ORDER BY seq DESC LIMIT 3, once per file per context window.

The model's own tools

memory_search (hybrid, with kinds), memory_timeline (session = :s AND seq BETWEEN :a AND :b), and memory_sql for any read-only question over the attributes.

-- "what failed in the planner yesterday?" through memory_sql
SELECT id, ts, text FROM memory
WHERE kind = 'error' AND MATCH(files, 'planner') AND ts >= 1791700000
ORDER BY ts DESC LIMIT 5

What to keep

Keep all of it. Raw events (prompts, answers, tool calls and results, the commentary between tool calls, compaction summaries) are the source of truth. Episode cards, summary sections and, next, model-written facts are keys derived from them, and can be rebuilt when the layout changes. Large tool outputs keep their head and tail, and file reads are stubs, since the file is on disk.

One trade-off left

On chat histories, 1,500-byte turns with no context gave the most correct answers (75.4%, against 73.0% for 400-byte windows; not significant). On coding sessions the windows win clearly. Engram is for coding sessions, so the windows stay. Cutting prompts and answers at 1,500 bytes and tool output at 400 is an untested middle path.

Next, in order of evidence

  1. Facts written by a model, as their own records. At Stop, in the background, a small model reads the turn and writes facts with the turn's id (kind = 'fact'). On LongMemEval this was the largest gain measured here: multi-session answers rose from 40% to 60%, and all-evidence coverage at 1,000 characters from 21% to 70%. It cost about $0.002 per 10,000 characters read. The model call must run with Engram's hooks off, or it would record itself.
  2. Time-aware queries. Temporal questions are the second-largest gap (68–74% against 94% with the oracle). Phrases such as "yesterday", "last week" or "before the refactor" map to a ts or seq range that Strata already filters on.
  3. HTTP hooks. Claude Code can POST hook events to a URL for every event except SessionStart, which stays a command hook and starts the daemon. That removes a process start from each tool call (see Execution time). The daemon would need a secret path and a Host check, so that web pages cannot write into memory through localhost.
  4. A reranker on the top candidates of prompts that pass the gate, which still cannot tell related from relevant well.
