Engram · Strata

Context that compounds.

Engram gives an AI coding agent a memory that lasts across sessions. Strata is the single-file search database underneath it: full text, filters, vectors and a graph, answered by one SQL statement. Together they let an agent remember what you told it last week, quickly and cheaply.

How it fits together

One memory, one file, one query language

Engram listens to a Claude Code session through hooks, distils what matters into notes, and recalls the right ones before each prompt. Everything lives in a Strata file, where every row is indexed four ways at once and a cost-based planner decides how to combine them.

How the agent uses it

Four milliseconds between your prompt and the right memory

The agent never has to remember to look things up. Claude Code calls Engram's hooks at fixed moments, and each hook is a handful of Strata queries against one table, memory, where every prompt, answer, tool call, error and distilled note is a row. Each row is indexed four ways at once, so one statement can mix them.

One table, four indexes, one query each

These are the shapes of the queries Engram runs, filled in with examples from the clinic project. The memory table's fields are id, session, kind, tag, turn, seq, ts, importance (columns), body, files (full text), emb (a 512-dimension vector) and links (graph edges).

Full textposting lists, BM25, Block-Max WAND

"What went wrong last time someone touched pricing?"

Before the agent edits a file, Engram finds earlier errors and decisions that mention it and injects the newest two.

SELECT ts, kind, text FROM memory
WHERE MATCH(files, 'pricing AND py')
  AND kind IN ('error', 'decision', 'fact')
ORDER BY seq DESC LIMIT 3;

Keyword recall uses ORDER BY bm25(body, :prompt). Strata's BM25 is 1.8–4.6× faster than Tantivy's.

Columnspacked fields, zone maps, facets

"Show me what happened around that error."

The memory_timeline tool reads a slice of one session in order. Every recall also uses columns to skip what is still in the context window.

SELECT seq, kind, tag, text FROM memory
WHERE session = 's-0412'
  AND seq BETWEEN 118 AND 132
ORDER BY seq;

-- what kinds of memory exist, at a glance
SELECT kind, COUNT(*) FROM memory GROUP BY kind ORDER BY 2 DESC;

Ranges, IN-lists and facet counts never touch the text or the vectors.

VectorsHNSW or flat, filtered search

"What do follow-ups cost now?"

The words don't match the note "Board: from 1 April a follow-up is $78", but the meaning does. Every prompt is embedded in 0.09 ms and searched by similarity, filtered to notes.

SELECT id, text, score() FROM memory
WHERE kind IN ('decision', 'fact', 'preference')
ORDER BY similarity(emb, :prompt) DESC LIMIT 50;

Strata answers vector top-10 in 0.09–0.20 ms; the planner picks pre- or post-filtering per query.

GraphEDGES field, REACHABLE, PATH, ppr

"Everything we decided about the invoice export."

Distilled notes link to the things they are about (e:invoice export, f:src/kestrel/export.py), to the turn they came from, and to the older note they supersede. One hop inward from an entity collects them all.

SELECT ts, kind, text FROM memory
WHERE REACHABLE(links, 'e:invoice export', hops => 1, dir => 'in')
ORDER BY ts DESC;

-- graph recall: the neighbours of the best hits, ranked by meaning
SELECT id, text FROM memory
WHERE REACHABLE(links, (SELECT id FROM memory
        ORDER BY similarity(emb, :prompt) DESC LIMIT 5),
      hops => 2, dir => 'both')
ORDER BY similarity(emb, :prompt) DESC LIMIT 20;

Two-hop traversals run at a 2.6 ms p95 over a million edges. Graph recall is opt-in today (ENGRAM_GRAPH=1) while it is measured on agent tasks.

All four in one statement

Strata's SQL lets a single statement filter by columns, require words, rank by meaning and walk the graph. The cost-based planner decides which index goes first.

SELECT ts, text FROM memory
WHERE kind = 'decision'                                  -- columns
  AND ts >= 1791000000                                   -- columns: a time range
  AND MATCH(body, 'privacy OR names')                    -- full text
  AND REACHABLE(links, 'e:invoice export', dir => 'in')   -- graph
ORDER BY rrf(bm25(body, :q), similarity(emb, :q)) DESC     -- text + vectors
LIMIT 5;

The model also gets five memory tools: memory_search (hybrid search), memory_timeline, memory_sql (read-only SQL over the table), memory_remember and memory_forget.

Engram · the kestrel benchmark

The agent remembers what the clinic owner said

Strata · graphs

Every row is a node. Every query can walk the graph.

Graph databases keep nodes and edges in stores of their own. Strata keeps one table: an EDGES field holds a row's outgoing links, each pointing at another row's key, optionally with a label and a weight. The same row still has its text, its fields and its embedding, so a traversal can start from a keyword search, a filter or a vector search, all in the same statement.

REACHABLE(f, seeds, hops)rows within n hops, out, in or both ways, filtered by label or by a predicate on every step
PATH(f, from, to)one shortest path, optionally only through rows that match a condition
hops()a row's distance from the seeds, usable in ORDER BY and SELECT
ppr(f, seeds)personalized PageRank as a score, fusable with BM25 and similarity through rrf()
-- the way in is a vector search: what its two best hits cite, ranked by similarity
SELECT id FROM papers
WHERE REACHABLE(cites, (SELECT id FROM papers ORDER BY similarity(emb, :q) DESC LIMIT 2))
  AND year >= 2018
ORDER BY similarity(emb, :q) DESC LIMIT 20;

-- PageRank from hybrid hits, fused with both rankings
SELECT id FROM papers ORDER BY rrf(bm25(body, :t), similarity(emb, :q),
  ppr(cites, (SELECT id FROM papers ORDER BY rrf(bm25(body, :t), similarity(emb, :q)) DESC LIMIT 2))) DESC LIMIT 20;

The graph finds what search alone misses

The test: given a new arXiv paper's title and abstract, find the papers it cites. 1,000 recent papers were held out of the table; half chose the one parameter, the other half are reported. The simplest graph plan wins: take the two papers nearest the query, follow their citations, rank what they cite by similarity. Papers on the same topic cite the same work, so their reference lists are better candidates than the papers themselves.

nDCG@20 for finding a paper's references, 484 held-out papers

Time per query under each method. Against BM25 and hybrid search the gain is +57% and +58%; p < 0.0001 against vector search. Edges built from vector similarity alone add nothing (0.079): the value comes from real relations the text does not carry.
Where it fits

Built for local, read-mostly retrieval

Good fit

  • Long-term memory for coding agents and assistants, on the developer's own machine.
  • Search over documents that carry metadata, embeddings and links: a desktop app's search box, an edge device, retrieval for a model on a laptop.
  • Anything that wants SQL and one file to copy, back up or ship.

Where others still lead

  • Tantivy counts facets 1.1–2.7× faster and is 1.8–2.9× faster on cold structured filters.
  • Loads that build the HNSW graph are 1.5–9× slower than SQLite's (0.9–1.5× without it).
  • SQL covers single-table SELECT; writes go through the Rust API. No joins, no clustering.
  • Graph hops across segments cost 2–5× an in-memory CSR array.

How these numbers were measured. Engram: 5 setups × 14 tasks × 3 repeats on the kestrel scenario, with Claude Code's own memory and the repository reset before every run, no user plugins loaded, and every answer graded by code. Every setup kept Claude Code's built-in memory notes. One task, can_book, defeated every setup. Seven runs first crashed the grader; after rebuilding each from its saved patch and regrading, three compacted-session invoice exports passed and four stayed at zero: two fresh runs declined to write the price function without the new prices, one raised an error for card holders, and one reminder run returned a result the grader could not read.

Strata: SQLite 3.53.2 with FTS5 and Tantivy 0.26.2 on SciFact, FiQA, TREC-COVID and Quora, one 4-core cloud VM, single-threaded queries, all systems fully merged. SQLite had no vector index, so its vector numbers measure a scan; a fuller comparison would add sqlite-vec and a dedicated vector store. Graph quality uses one task and one static embedder; a stronger embedder would raise the vector baseline.
